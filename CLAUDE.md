- **REFM standing invariants** (each born from a measured defect; the full dated story is in [CHANGELOG.md](CHANGELOG.md), the general lessons in [docs/TRAPS.md](docs/TRAPS.md)):
  - **Asset strategy changes are a MODEL operation**, not a field write: `lib/state/strategySwitch.ts` (pure) parks the outgoing strategy's sub-units, opex and companion in `Asset.retainedByStrategy` and restores or seeds the incoming set; `state.subUnits` / `costLines` / `costOverrides` hold ONLY the active strategy's rows. Dialog and banner are gated on `assetHasStrategyAssumptions`; the dropdown previews via a DRY RUN of the same pure function the store commits.
  - **Allocation shares never silently sum to zero**: every share basis falls back to `equalPhaseShare` when its denominator is zero (six call sites in `resolveAllocationFactor` / `resolveDriverFactor`); factors are proven to sum to exactly 1. Never write `return total > 0 ? mine / total : 0`.
  - **`marketing` is a COST STAGE** (`CostStage = land | hard | soft | marketing | operating`), so construction cost excluding land also excludes marketing. When adding a stage: only `Record<CostStage, number>` sites are compiler-guarded, two inferred literals in `Module1Costs.tsx` will silently drop it, and `deriveCostType` defaults an unhandled stage to `'hard'`.
  - **A parcel is PROJECT-WIDE**: the explicit parcel lookup is project-wide; the implicit rules (autoByBua / percent / equal share) stay phase-scoped. `computeAssetLandBreakdown` returns `rateIssue` so there is no silent zero land value.
  - **One placement / window rule each**: `phaseLocalToProjectIndex` is the ONE Y0 upfront-lump rule (all five sites call it); `deriveCostWindow` is the ONE seeded cost-window rule (seed + store re-derive); a followed phasing source (collections, land cash) replaces the WINDOW, not just the shape, and the row renders `resolvedWindowByLineId`, what the engine spent on.
  - **The capex table is an ordered, user-classified list**: `% of selected lines` is POSITIONAL and upward-only (`src/core/calculations/selectedBase.ts`, shared by picker and engine); stage is a per-line `stageOverride` read through `deriveCostStage` (the id map outranks `stage`); order edits go through `insertCostLineNear` / `moveCostLine`; case overrides are id-keyed.
  - **A cost line is a catalog entry plus a label** (`CostLine.catalogId`, `lib/state/costCatalog.ts`, mig 214; **ACCOUNT-scoped since mig 241**, one vocabulary per client firm shared by every member, author kept with SET NULL): selecting an entry STAMPS behaviour onto the LINE; the catalog is never read by the engine, reports or exports; identity resolves from the base id via `resolveCatalogId` when `catalogId` is absent. Never resolve identity a second way (the minted `custom-<ts>__<phase>` shape defeats base-id-only rules).
  - **Cost of sales is computed ONCE, by Module 2** (`lib/costOfSales.ts`): the capex base, the capitalised IDC inside it and the spread on the recognition share are assembled there and nowhere else, and the P&L, the balance-sheet inventory, the Module 2 screen, both PDFs and the workbook all READ `snap.byAssetCostOfSales`. A second engine (`costOfSalesV2`) drove the screen and the exports until 2026-08-30 and was 407,131,731 from the P&L in one year while agreeing to 0.24% over the lifetime; it is deleted. `computeAssetCost.perPeriod` now sums to `.total` (it truncated any line distributed past its window), and a Sell asset inventory roll-forward closes at ZERO, which is the cheap reconciliation that exposed all of it. The tab's FIRST table is the year-by-year BUILD of the base (Module 1 capex + capitalised IDC = total base, then the recognition share and the charge, footed by a check row); both halves and the share are CARRIED on the result, never recomputed by a surface. See [docs/TRAPS.md](docs/TRAPS.md) 7.31, 3.8 and 3.9.
  - **Selling costs belong to revenue**: scope via `deriveAssetScope` (ONE implementation in `selectedBase.ts`), enforced in `assetVisibleLines`, which the Costs tab, the engine and the copy planner all call, so shown is charged and hidden is not. Bases come from the revenue module; **zero is not absent** (a held asset's sale base is 0, never a fallback). `computeAssetCost` takes the revenue snapshot and resolves bases internally (`core/calculations/revenue/sellingCosts.ts`, zero imports); every reachable call site values a line the same way.
  - **No country gate, no silent lock**: `assetVisibleLines` takes no country (the gate is RETIRED; RETT is a catalog entry the user adds); view mode is visibly read-only, `modelLocked` -> `viewLocked` is ONE derivation, inputs are locked by CSS + capture handlers, and a mutating button must declare `data-view-mutates="true"` to be locked (buttons are opt-IN, inputs opt-OUT via `data-view-editable`).
  - **A facility share is used exactly as typed** (`resolveFacilityShares`, verbatim, floored at zero; equal split only when NO share is typed anywhere); a wrong sum is STATED with a one-click repair, never rescaled. A facility's schedule is project-wide (share x requirement), so identical tables are shares, not double counts.
  - **Migrations spread the raw object and normalise on top**, never enumerate the fields they keep (three fields were lost to the whitelist shape); no legacy rename key may be a current catalog id. `Project.country` is an ISO code selected on Project & Phases; `countryMatches` resolves BOTH sides of any comparison.
  - **Depreciation starts when the asset is available for use** (`offset + cp - 1`, in PERIODS, `computePhaseTimeline` needs `modelType`), for BOTH streams that feed `AssetPL.daPerPeriod` (own capex AND capitalised IDC).
  - **Returns chain**: FCFF is UNLEVERED FULL COST (in-kind land charged, no interest / IDC row); FCFE builds VISIBLY from FCFF with the terminal swap as two rows; the finance-cost ledger foots `Opening + Charge - Paid = Closing` at 0.00; interest is one line per origin. The deficit sizing has NO finance cost in it, gates on `capex > 0`, and measures IDC headroom pre-interest (Schedules R112-R124). The management fee funding toggle (`fundTerms.managementFeeFunding`, deficit default | equity) lives on Financing AND Fund Terms, one field; the equity-funded fee is its own capped `dedicatedEquity` draw and the reconciliation compares against BOTH halves per period. In-kind equity reads `capex.perPeriod.landInKind` verbatim (no parcel-walk fallback); the in-kind pair sits INSIDE the totals; max |Assets - L&E| is 0.00 on both live projects.

## Authentication (summary)

Two independent stacks. Full per-flow detail (sign-in / register / OTP / device trust / admin bypass) in [CLAUDE-FEATURES.md](CLAUDE-FEATURES.md).

- **Training Hub** (learn.): custom session `training_session` cookie + bcrypt password in `training_passwords`. Source of truth = Google Apps Script roster. `email_confirmed` is `!== false`-truthy (null counts as confirmed for pre-migration-027 students).
- **Modeling Hub** (app.): NextAuth.js Credentials JWT (1hr) + scrypt password in `users.password_hash`. Admin role bypasses both EmailNotConfirmed + DEVICE_VERIFICATION_REQUIRED checks.
- **Device trust**: shared `fmp-trusted-device` cookie + `trusted_devices` table (30-day, keyed by email not UUID).

## Subdomain Routing (`next.config.ts`)

- `learn.fmp.com/` -> rewrites to `/training`. `app.fmp.com/` -> rewrites to `/modeling`. URL unchanged in both.
- Clean auth URLs `/signin`, `/register`, `/forgot` resolve per-subdomain to the matching training / modeling page.
- Cross-domain main-site paths redirect to `financialmodelerpro.com`.

Navbar uses plain `<a>` with absolute URLs via `NavbarServer.absolutizeHref()` + file-level `APP_URL` / `LEARN_URL` constants (never raw `process.env`).
