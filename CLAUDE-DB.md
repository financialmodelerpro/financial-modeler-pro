**Upload caching rule (2026-08-01).** An upload that passes no `cacheControl` gets Supabase's default `max-age=3600`, so an immutable asset is revalidated hourly forever. Every public-image upload path now passes one of the two constants in `src/shared/storage/cacheControl.ts`, chosen by ONE question, can the bytes at this path ever change: `STORAGE_CACHE_IMMUTABLE` (1 year) for timestamped / uuid paths, where a replacement writes a NEW url (`cms-assets` media + site-settings, `avatars` both routes); `STORAGE_CACHE_REPLACEABLE` (5 min) for stable paths overwritten with `upsert: true` (`live-session-banners/banners/<sessionId>`, the `generate-images` fixed names), where a long cache would show an admin the OLD image after they replaced it. **Reading these headers back: use a ranged GET (`Range: bytes=0-0`), never HEAD.** The CDN answers HEAD with a blanket `cache-control: no-cache` whatever the object stores, which reads as "nothing is cached" and is how the 2026-07-30 perf audit reached that (wrong) conclusion. `cms-assets/optimized/*` holds the resized marketing images (see `scripts/optimize-marketing-images.ts`); the full-size originals are retained beside them.
